# Смена — дневник смен водителя

Небольшое full-stack приложение для учёта поездок водителя. Сервер хранит данные в JSON, считает дневную сводку и идемпотентно принимает новые поездки; адаптивный веб-клиент показывает показатели и позволяет переключать дни.

## Что сделано

- дневная сводка: число поездок, выручка, комиссия, сумма «на руки»;
- разбивка выручки и количества поездок по наличным и карте;
- список поездок за выбранный день и навигация по датам;
- добавление поездки из интерфейса или напрямую через API;
- проверка суммы, комиссии, дат и способа оплаты;
- защита от повторной записи по уникальному `id`, включая параллельные запросы;
- атомарная запись JSON-файла;
- unit-тесты расчёта сводки, валидации и защиты от дублей.

## Запуск

Нужен **Node.js 22+**. Внешние зависимости не используются.

```bash
npm start
```

Откройте [http://localhost:3000](http://localhost:3000). Для разработки с автоматическим перезапуском:

```bash
npm run dev
```

Тесты:

```bash
npm test
```

## API

### Получить поездки и сводку за день

```http
GET /api/day?date=2026-10-01
```

Ответ содержит `date`, `summary` и `trips`. День поездки определяется по календарной дате в поле `start` с сохранением указанного в ISO-строке часового пояса.

### Добавить поездку

```http
POST /api/trips
Content-Type: application/json

{
  "id": "t6",
  "start": "2026-10-01T14:10:00+05:00",
  "end": "2026-10-01T14:32:00+05:00",
  "amount": 2100,
  "payment": "card",
  "commission": 315
}
```

- `201 Created` — поездка добавлена;
- `200 OK` и `"duplicate": true` — запрос с таким `id` уже был обработан, дубль не создан;
- `400 Bad Request` — данные не прошли проверку.

Для отдельного файла данных задайте переменную `TRIPS_FILE`, для другого порта — `PORT`.

## Структура

```text

src/server.js    HTTP API и раздача клиента
public/          веб-интерфейс

```

## Как использовался ИИ

ИИ помог быстро подготовить каркас сервера, интерфейс и набор тестовых сценариев. Результат был проверен вручную: отдельно уточнена работа с датой из ISO-строки (без неявного перевода в UTC), добавлена очередь записи для защиты от гонки при параллельных запросах и атомарная замена JSON-файла. Эти детали были скорректированы после проверки первоначального подхода, в котором простая схема «прочитать — проверить — записать» могла создать дубль при одновременных запросах.
